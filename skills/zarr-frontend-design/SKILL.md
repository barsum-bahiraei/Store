# ZARR Frontend Design

برای درخواست‌های مربوط به ظاهر، تجربه کاربری، ریسپانسیو بودن و کامپوننت‌های رابط کاربری پروژه ZARR استفاده شو.

## مرز قطعی

- فقط فایل‌های فرانت‌اند را تغییر بده: `Panel/` و `Website/`.
- به هیچ عنوان فایل‌های `Backend/`، کنترلرها، سرویس‌ها، مدل‌ها، دیتابیس، migrationها یا قراردادهای API را تغییر نده.
- اگر تغییر UI به تغییر API یا بک‌اند نیاز داشت، آن نیاز را گزارش کن و فقط راه‌حل فرانت‌اندیِ سازگار با قرارداد فعلی را بررسی کن.
- از بازنویسی گسترده یا تغییر معماری موجود بدون نیاز مستقیم درخواست خودداری کن.

## تشخیص اپلیکیشن

- `Panel`: React 19، React Router 7، Vite و Tailwind CSS 4.
- `Website`: Next.js 16، React 19 و Tailwind CSS 4.
- قبل از ویرایش، مسیر و الگوی موجود همان اپلیکیشن را شناسایی کن و الگوی همان بخش را ادامه بده.
- از اضافه کردن کتابخانه UI جدید خودداری کن مگر اینکه کاربر صریحاً درخواست کند یا وابستگی موجود پاسخ‌گو نباشد.

## زبان و هویت بصری

- رابط کاربری فارسی و RTL را پیش‌فرض در نظر بگیر؛ جهت، فاصله‌ها، آیکن‌ها، ترتیب ستون‌ها و رفتار موبایل را برای RTL بررسی کن.
- از فونت‌های موجود IRANSans در assets همان اپلیکیشن استفاده کن و فونت جدید اضافه نکن مگر با درخواست کاربر.
- رنگ، radius، سایه، typography و فاصله‌گذاری را از الگوهای موجود استخراج کن و در کامپوننت‌های جدید یکپارچه نگه دار.
- ظاهر باید تمیز، خوانا، کاربردی و متناسب با نقش صفحه باشد؛ برای داشبورد، تراکم اطلاعات و سلسله‌مراتب بصری را بر زیبایی تزئینی مقدم بدان.

## روش اجرا

1. ابتدا فایل‌های مرتبط، layout، styleهای سراسری و کامپوننت‌های مشابه را بررسی کن.
2. مشخص کن تغییر در `Panel` است یا `Website` و فقط همان محدوده را هدف بگیر.
3. قبل از پیاده‌سازی، حالت‌های اصلی UI را در نظر بگیر: loading، empty، error، موفقیت، disabled و responsive.
4. از کامپوننت‌ها و utilityهای موجود استفاده کن؛ کد تکراری جدید نساز مگر اینکه الگوی قابل استفاده مجدد ایجاد شود.
5. در صورت نیاز به داده، قرارداد API و مدل‌های موجود را فقط بخوان و مصرف کن؛ آن‌ها را تغییر نده.
6. پس از تغییر، typecheck، lint یا build مرتبط با همان اپلیکیشن را اجرا کن و خطاهای ناشی از تغییر فرانت را اصلاح کن.
7. نتیجه را در اندازه‌های موبایل و دسکتاپ بررسی کن و تغییرات بک‌اند را با `git diff -- Backend` کنترل کن.

## کیفیت رابط کاربری

- در موبایل از overflow افقی ناخواسته جلوگیری کن.
- برای فرم‌ها label، حالت focus، خطای قابل فهم و وضعیت disabled داشته باش.
- دکمه‌ها و عناصر تعاملی باید حالت hover، active و keyboard focus داشته باشند.
- کنتراست متن و پس‌زمینه را حفظ کن و اطلاعات مهم را فقط با رنگ منتقل نکن.
- جدول‌ها، کارت‌ها و نمودارها باید در عرض کم قابل استفاده بمانند.
- تغییرات بصری را محدود و قابل توضیح نگه دار؛ رفتار فعلی و مسیرهای کاری را بدون درخواست کاربر تغییر نده.

## گزارش نهایی

در پایان، خلاصه‌ای از فایل‌های فرانت‌اند تغییرکرده، تست‌های اجراشده و هر محدودیت باقی‌مانده را گزارش کن و صریحاً تأیید کن که بک‌اند تغییر نکرده است.
