در پروژه، یک سری API جدید به بک‌اند اضافه شده و همچنین بعضی از Entityها برای پنل ادمین تغییر کرده‌اند.

لطفاً پروژه را کامل بررسی کن و فقط کارهایی را انجام بده که در ادامه مشخص شده است:

### 1. اتصال APIهای جدید به فرانت‌اند

APIهای جدیدی که در بک‌اند اضافه شده‌اند را بررسی کن و هر APIای که هنوز در فرانت‌اند پنل ادمین متصل نشده، به فرانت‌اند متصل کن.

* قبل از پیاده‌سازی، APIهای موجود در Swagger را با APIهای فعلی فرانت مقایسه کن.
* APIهایی که از قبل به‌درستی متصل هستند را دوباره‌کاری نکن.
* فقط APIهای متصل‌نشده را پیاده‌سازی و به UI مربوطه وصل کن.
* الگوی فعلی پروژه، Axios، State Management و ساختار موجود فرانت‌اند را حفظ کن و معماری جدیدی بدون نیاز ایجاد نکن.

Swagger:
https://localhost:7185/swagger/index.html

### 2. هماهنگ‌سازی نام Entityها بین Backend و Frontend

Entityهایی که در بک‌اند تغییر نام داده‌اند یا ساختارشان تغییر کرده، بررسی کن و نام‌ها و مدل‌های مربوط به آن‌ها را در فرانت‌اند با بک‌اند هماهنگ کن.

* تمام Type/Interface/Model/DTOهای مرتبط را بررسی کن.
* نام فیلدها، روابط و ساختار Response/Request را با API جدید هماهنگ کن.
* اگر تغییر نام Entity باعث خرابی importها، serviceها، storeها یا componentها شده، آن‌ها را اصلاح کن.
* از تغییرات غیرضروری در ساختار پروژه خودداری کن.

### 3. بررسی مشکلات Backend که جلوی ادامه کار پنل ادمین را می‌گیرند

در حین اتصال APIها، اگر متوجه شدی سمت بک‌اند مشکلی وجود دارد، آن را بررسی کن.

فقط مشکلاتی را که باعث می‌شوند فرانت‌اند نتواند کار پنل ادمین را ادامه دهد یا یک قابلیت اصلی بلااستفاده بماند، اصلاح کن.

مثلاً:

* API اشتباه یا ناقص
* Request/Response نامتناسب با فرانت
* DTO اشتباه
* Route اشتباه
* Authorization/Access مشکل‌دار
* Relationship اشتباه
* Validationای که باعث شکست API می‌شود
* Status Code نامناسبی که عملکرد فرانت را مختل می‌کند
* مشکل EF Core یا Repository/Service که باعث خطای API می‌شود

اگر مشکل مهمی در بک‌اند دیدی که بهتر است اصلاح شود ولی مستقیماً جلوی کار فرانت را نمی‌گیرد، آن را تغییر نده؛ فقط در پایان گزارش بده و پیشنهاد اصلاحش را بنویس.

### 4. ساخت Roleهای اولیه

سیستم Role را طوری Seed/Initialize کن که ثبت‌نام کاربر جدید به خاطر نبودن Role با خطا مواجه نشود.

دو Role داشته باشیم:

#### Role اول

* Id: `1`
* Name: `User`
* این Role برای کاربر معمولی باشد.
* هنگام Register شدن کاربر جدید، Role پیش‌فرض او همین Role باشد.

#### Role دوم

* Id: `2`
* Name: `Owner`
* تمام Accessهای موجود سیستم را داشته باشد.
* تمام Permission/Accessهای فعلی را به این Role اختصاص بده.
* اگر Access جدیدی در سیستم وجود دارد، آن را هم در نظر بگیر تا Owner دسترسی کامل داشته باشد.

دقت کن که این Seed به شکلی پیاده‌سازی شود که در اجرای Migration/Startup باعث Duplicate شدن داده‌ها یا خطای Database نشود.

### قوانین مهم

* ابتدا ساختار فعلی پروژه را بررسی کن و بعد تغییر بده.
* کدهای موجود و معماری فعلی را حفظ کن.
* چیزی را که سالم است بازنویسی نکن.
* APIهایی که قبلاً متصل هستند را دوباره پیاده‌سازی نکن.
* فقط APIهای جدید و متصل‌نشده را به فرانت وصل کن.
* تغییرات Entityها را در کل فرانت به‌صورت کامل دنبال کن تا هیچ Reference قدیمی باقی نماند.
* اگر برای اتصال یک API نیاز به اصلاح جزئی بک‌اند است، اصلاحش کن.
* اگر مشکلی ارتباطی با ادامه کار پنل ندارد، فقط گزارش بده و بی‌دلیل کد بک‌اند را تغییر نده.
* بعد از اعمال تغییرات، پروژه را Build/Type-check کن و خطاهای ایجادشده را برطرف کن.
* در پایان دقیقاً گزارش بده:

    1. چه APIهایی به فرانت متصل شدند.
    2. چه Entityهایی در فرانت هماهنگ شدند.
    3. چه مشکلات Backend اصلاح شدند.
    4. چه مشکلاتی باقی مانده‌اند که فعلاً جلوی ادامه کار را نمی‌گیرند.
    5. Roleهای `User` و `Owner` چگونه Seed شدند.
    6. چه Accessهایی به Owner داده شده‌اند.
